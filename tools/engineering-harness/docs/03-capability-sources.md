# Capability Sources

能力源是 agent 可以感知或驱动的外部和内部系统。能力源本身不等于工程判断，必须被 harness 协议组织起来。

## 代码结构源

代表工具：codebase-memory-mcp、源码、TypeScript AST、tree-sitter、language server。

适合回答：

- 某个组件、函数、类在哪里。
- 谁调用了它。
- 修改它会影响哪些地方。
- 有没有类似实现。
- 哪些代码可能已经废弃。

不适合单独回答：

- 业务语义是否正确。
- 是否符合领域边界。
- 是否应该复用。
- Figma 设计意图是什么。

## 设计源

代表工具：Figma MCP、Figma Code Connect、设计系统库。

适合回答：

- 设计节点结构。
- 视觉尺寸、颜色、字体、间距。
- 组件实例和变体。
- 截图与导出资产。

风险：

- Figma 可能缺失行高。
- SVG 可能被错误内联到页面。
- 设计组件不一定和代码组件一一对应。
- 设计稿结构不等于工程结构。

## 外部知识源

代表工具：Google/Web MCP、OpenAI docs、官方文档、标准规范。

适合回答：

- 最新 API 行为。
- 第三方库能力。
- 行业最佳实践。
- 安全和合规信息。

风险：

- 外部资料不一定适合当前项目。
- 非官方资料可能过时或错误。
- 必须把外部结论映射回项目约束。

## 项目记忆源

代表文件：`AGENTS.md`、`ARCHITECTURE.md`、`docs/product/domain.md`、`docs/architecture/`、`docs/adr/`、README、设计文档、产品规格。

适合回答：

- 团队术语。
- 架构边界。
- 历史决策。
- 禁止事项。
- 质量标准。

风险：

- 文档可能腐烂。
- 过长文档会增加 token 压力。
- 文档必须和源码、检查脚本、测试和 skill 保持接近。

## 执行反馈源

代表来源：lint、typecheck、unit test、e2e、Playwright 截图、日志、构建输出、浏览器 DevTools。

适合回答：

- 当前实现是否可运行。
- 视觉是否符合预期。
- 变更是否破坏现有行为。
- agent 的假设是否成立。

风险：

- 测试覆盖可能不足。
- 截图检查需要明确验收点。
- 失败输出需要先归因再修复。
