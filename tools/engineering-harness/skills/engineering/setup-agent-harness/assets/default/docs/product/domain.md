# Domain Language

Record the canonical product and domain terms that agents must use when planning, naming code, writing tests, and explaining changes.

Use this file for:

- Core nouns and workflows.
- Terms that must not be replaced by looser synonyms.
- Product ownership and lifecycle rules.
- Domain-specific naming rules.
- Places where raw external vocabulary must be translated into project language.

Do not use a root `CONTEXT.md` as the long-term source of truth. If one exists during setup, migrate or map its useful content into this file, `docs/architecture/`, `docs/adr/`, `docs/design/`, or `docs/quality/`.
