# Harness Loop

## Orient

Classify the task and load the minimum relevant guides.

## Retrieve

Find existing implementations, design facts, external facts, and relevant tests before changing code.

## Plan

Decide reuse, placement, risks, and validation evidence.

## Act

Make the smallest useful change while respecting project boundaries.

## Observe

Collect feedback from sensors: commands, tests, browser, logs, screenshots, or MCP responses.

## Evaluate

Compare evidence against the project's verification gates.

## Learn

If a rule was missing, identify where it should be written back.

## Govern

Watch for repeated failures, stale docs, duplicate implementations, and weak sensors.
